# 依頼キューの処理

引数にタスクのID(例: `t-ab12cd34`)があれば、そのタスクだけを処理する。なければ待機中をすべて処理する。

## 手順
1. `CLAUDE.md` と `docs/SCHEMA.md` を読む(読んでいなければ)。
2. `data/biz.json` を読み、`tasks` から `assignee` が `claude` で `status` が `todo` のものを集める。なければ「待機中の依頼はありません」と伝えて終わる。
3. `priority` の高い順、同じなら `due` の早い順に並べる。
4. タスクを1件ずつ、次の流れで処理する。
   1. `status` を `doing` にし、`updatedAt` を更新し、`log` に「依頼を開始: <title>」を足す。**この書き込みを先にして、画面に作業中と出す。**
   2. `notes` の指示と、`ref` の関連項目(商品・ツール・情報)を読む。
   3. `kind` に応じて作業する。
      - `research`: Web検索で調べる。結果は `intel`(`source: "claude"`、`status: "新着"`)、`tools`(`status: "気になる"`)、商品の `notes` などの適切な場所に書く。出典URLと確認日を必ず添える。
      - `build`: 成果物を `products/<スラッグ>/` に作り、商品の `folder` を更新する。
      - `write`: 文章を作り、商品フォルダにファイルで保存する。短い要点は `result` にも書く。
      - `review`: 数値・計算・規約を検算し、問題点と修正案を `result` に書く。確認できないものは「未確認」と書く。
   4. `result` に、やったことと結果の場所を3〜8行で書く(出典URL・確認日を含める)。
   5. `status` を `done` にし、`doneAt` と `updatedAt` を更新し、`log` に「依頼を完了: <title>」を足す。
5. 公開・出品・決済・送信などが必要になったら、実行せずに `status` を `todo` に戻し、`result` に「ここで確認が必要: <内容>」と書いて利用者に聞く。
6. 最後に、チャットで3行以内に報告する(処理した件数 / 結果の見る場所 / 次の一手)。

## 注意
- 1件の処理が終わるたびに `data/biz.json` を保存する。まとめて最後に書かない。
- 書く前に必ずファイルを読み直す(画面が同時に書くため)。
- 調べても分からなかったことは、推測で埋めず「未確認」と書く。
